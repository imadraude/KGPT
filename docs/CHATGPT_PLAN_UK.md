# ChatGPT Plus у KGPT / SwiftKey

**Статус:** експериментальна інтеграція у гілці feature/chatgpt-plan-oauth. Авторизація на пристрої ще не протестована.

## Зміни

- Додано окремого провайдера ChatGPT Plan, не змінюючи звичайний OpenAI API та Gemini.
- Офіційна авторизація Continue with ChatGPT із динамічною реєстрацією OAuth, PKCE, state, nonce, зворотним викликом на 127.0.0.1.
- Криптографічна перевірка ID-токена за JWKS та перевірка окремого дозволу chatgpt.tokens.use.direct.
- Зберігання токенів в Android Keystore (AES-GCM) у локальному каталозі без резервного копіювання, зі збереженням нових refresh-токенів.
- SwiftKey передає лише текст запиту окремому сервісу KGPT, не отримуючи токенів. Сервіс перевіряє UID застосунку-виклику.
- Для Responses API застосовуються store:false і stream:true та контроль завершення response.completed.
- Екран облікового запису дозволяє переглянути моделі, доступні користувачу, через GET /v1/models.
- GitHub Actions збирає тестовий APK для перевірки коду.

## Перевірка

1. Перевірити успішність збірки Android у GitHub Actions.
2. Встановити тестову версію KGPT на Android і налаштувати модуль для SwiftKey за документацією KGPT.
3. Відкрити KGPT → Models → ChatGPT Plan. Завершити авторизацію в системному браузері.
4. Підтвердити окремий дозвіл на використання підписки.
5. На екрані підключення переглянути доступні моделі, вибрати назву моделі в KGPT та зберегти налаштування.
6. Викликати команду KGPT для тексту у SwiftKey, перевірити відповідь.

## Безпека та обмеження

- Текст передається OpenAI лише при виклику команди ШІ. Не передавайте паролі, коди доступу чи іншу конфіденційну інформацію.
- Підписка ChatGPT має спільні ліміти використання.
- Локальне від'єднання не відкликає дозвіл на боці OpenAI — відкличте його в налаштуваннях ChatGPT.
- Поки реалізовано лише один обліковий запис на інсталяцію.
- Вхід через loopback, сумісність Android 16 і SwiftKey та захист IPC потребують реального тестування й аудиту.
- Не публікуйте цю гілку як перевірений готовий реліз до тестів.


## Аудит і виправлення авторизації (7 листопада 2026)

- Повторні та паралельні зворотні виклики браузера/ручного введення тепер мають одну контрольовану сесію. Після скасування результат попередньої спроби ігнорується.
- Перевіряється адреса callback (127.0.0.1, порт та шлях), одноразовий state без дублікатів, виданий client_id та фактично надані OAuth-дозволи. Раніше відсутній scope помилково вважався наданим.
- Окремо запитується згода, якщо попередня авторизація не надала доступ до підписки.
- Незавершена авторизація, включно із PKCE-кодом, nonce та state, зашифровано зберігається в каталозі no_backup протягом 10 хвилин. Якщо Android закриє застосунок під час входу, відновіть його та вставте повне зворотне посилання.
- Для **першої** авторизації потрібне повне посилання із code, state та client_id; сам код не містить виданого ідентифікатора клієнта.
- У вікні входу є **Скасувати поточний вхід**, після чого можна почати нову спробу.
- Поновлення OAuth-токенів не тримає заблокованими налаштування під час мережевих запитів. Ротація refresh token виконується послідовно, одночасно з access token.
- Після HTTP 401 запит допускає одну повторну спробу з оновленим токеном; при тимчасовій помилці токени не очищаються.
- Помилки доступності підписки, ліміту, регіону, моделі та зв'язку обробляються окремо; через SwiftKey не передаються токени чи відповіді сервера з конфіденційними даними.
- CI перевіряє збирання APK та запускає локальні JUnit-тести захисту OAuth.

**Перевірка на телефоні все ще потрібна.** Успішна збірка не доводить, що обліковий запис, регіон та конкретна модель допущені OpenAI до планового використання. Наразі підтримується одне реєстраційне налаштування на інсталяцію. Локальне від'єднання не відкликає доступ на сервері: це слід зробити в налаштуваннях ChatGPT.

## Виправлення зворотного виклику (7 листопада 2026)

Виправлено помилку `OAuth redirect URI mismatch` під час **автоматичного** повернення з браузера. HTTP-сервер отримував лише шлях `/auth/callback?...`, а KGPT відтворював повний URL без фактичного порту сервера. Перевірка OAuth правильно відхиляла таку адресу. Тепер KGPT відновлює повну адресу із портом, на якому сервер прийняв запит, а потім проводить звичайні перевірки шляху, порту та `state`.

Додані локальні регресійні тести для змінних портів і недійсних HTTP-шляхів. Після встановлення оновленої збірки **почніть новий вхід**, не використовуйте зворотні посилання з попередніх спроб: вони містять одноразовий код та `state`, пов'язані з конкретною сесією.
